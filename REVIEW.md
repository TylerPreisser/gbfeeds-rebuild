# REVIEW.md — how code review works in gbfeeds-rebuild

Read `DECISIONS/` before reviewing anything. Conformance to an Accepted ADR is never a defect.

## The citation bar — prove it or discard it

A finding that cannot cite the code it breaks is **DISCARDED**: not filed, not "worth a look", not
a non-blocking note. There is no fourth bucket.

1. **`file:line` in real source, every time.** Never infer behavior from a name, a comment, or a
   type. If you did not open the file, you have no finding.
2. **Read the implementation, not the diff.** Trace the complete call path and every caller of the
   changed symbol; read the nearby tests and the git history for that file.
3. **Construct a concrete failing scenario** — the input, the path it takes, the wrong output.
   "This could break if…" is not a scenario.
4. **Discard the candidate** if an existing guard handles it, the behavior is intentional and
   documented (comment, ADR, test), or you cannot demonstrate the failure.
5. **Score 0–100 and drop everything under 80.** False positives cost more than misses here.
6. **"Fixed"/"done" requires command output from this turn** — a build or test log in the
   transcript. A green suite is not proof of correctness; another reviewer agreeing is not evidence.
7. Findings are written up with IDs first. Fixes happen only after explicit authorization.
8. Grounding cuts both ways: do not wave a real, cited finding away as a false positive on vibes.

**Out of scope for a report:** style preferences, speculative future risk, feature requests,
anything outside the changed lines, and anything `npm run lint` or `tsc --noEmit` already catches.

## Must-check for this repo

Check these against real source before approving — each has a build gate or a boundary behind it:

- **Layer direction.** `atomic/` importing `composite|page|motion|decoration`, `composite/`
  importing outside `atomic|decoration|lib|hooks|types`, `motion/` importing `data/`, or an
  `src/app/**` file importing a component below `page/` — all defined at `eslint.config.mjs:24`-`:78`.
- **`'use client'` importing `@/data/*`** outside the four justified entries in
  `scripts/validate-client-data-boundary.ts:19`-`:36`. A new allowlist entry with no written reason
  is a finding.
- **`next/image` imported anywhere but `src/components/atomic/Image.tsx`**, or the bare `motion`
  export imported from framer-motion instead of `LazyMotion` + `m`
  (`eslint.config.mjs:90`-`:107`).
- **Static-export violations.** `next.config.ts:7` is `output: 'export'`: no route handlers, no
  server actions, no request-time data fetching, no middleware assumptions. Anything needing a
  server belongs in `cloudflare-worker/`.
- **Trailing slash + base path.** `trailingSlash: true` (`next.config.ts:8`); runtime asset paths
  go through `withBasePath()` (`src/lib/basePath.ts:3`) or they 404 on the GitHub Pages build.
- **Schema drift.** A product/harvest field added to `src/lib/validators.ts` but not to the build
  gate's own inline schema in `scripts/validate-products.ts` / `scripts/validate-harvests.ts`
  (or vice versa) — the two copies are independent.
- **Secrets.** `RESEND_API_KEY` and `TURNSTILE_SECRET_KEY` are FORBIDDEN in the Next.js build env
  and hard-fail the build (`scripts/verify-env.ts:18`); they belong to the Worker only. Any new
  `NEXT_PUBLIC_*` is public by definition.
- **Reduced motion.** A new animation with no `useReducedMotion()`
  (`src/hooks/useReducedMotion.ts:20`) escape hatch, or a scroll-driven page not added to the
  Lenis route list at `src/components/motion/MotionProvider.tsx:23`-`:35`.
- **E2E asserted against a stale `out/`.** `npm run test:e2e` serves the export, not `next dev`
  (`playwright.config.ts:34`-`:39`) — a spec added without a preceding `npm run build` proves nothing.

## Skip rules — do not review, do not report findings in

- `node_modules/`, `package-lock.json` (and any other lockfile)
- `.next/`, `out/`, `test-results/`, `playwright-report/`, `.lighthouseci/`, `coverage/`
- `graphify-out/` — generated knowledge graph, never committed
- `next-env.d.ts`, `tsconfig.tsbuildinfo` — generated by the toolchain
- `_inherited_assets/` — vendored read-only assets from the legacy site, not rebuild source
- `public/**` binary assets (images, fonts) — review the reference to them, not the bytes
- Anything already ignored at `eslint.config.mjs:123`-`:136`

## Reproduce locally before filing

```
npm ci && npm run lint && npm run type-check && npm run test:unit && npm run build && npm run test:e2e
```

That is the same order as the CI gate in `.github/workflows/deploy.yml`. Paste the real output.
Kill `next dev` (:3000) and `serve` (:4173) before you finish.
